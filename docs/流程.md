## 一、整体业务流程

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  添加竞品    │────→│ 配置监控URL  │────→│ 手动点击抓取 │
│ (竞品管理)   │     │  官网/定价页  │     │  [立即抓取]  │
└─────────────┘     └─────────────┘     └──────┬──────┘
                                                │
                                                ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  查看报告    │←────│  AI一次调用  │←────│  Diff对比   │
│ (手动生成)   │     │ 分类+摘要    │     │ 文本相似度  │
└─────────────┘     └─────────────┘     └──────┬──────┘
                                                │
                                         ┌──────┴──────┐
                                         │  情报事件    │
                                         │  (事件列表)  │
                                         └─────────────┘
```

**数据对象关联链：**
```
Competitor（竞品）→ Snapshot（网页快照）→ Intelligence Event（情报事件）
                                                        ↓
                                              Weekly Report（周报）
                                                        ↓
                                              Trend Insight（趋势洞察）
```

---

## 二、功能模块梳理

| 模块 | 核心功能 | 解决的问题 |
|---|---|---|
| **LandingPage** | 产品价值展示、功能介绍、CTA引导 | 让访客了解产品并注册 |
| **LoginPage** | 登录/注册、多方式认证 | 用户身份验证 |
| **Dashboard** | 今日概览、关键指标、最新情报、趋势图 | "今天有什么值得我关注的？" |
| **竞品管理** | 添加/编辑/删除竞品、配置监控URL、设置频率 | "我要监控谁？监控什么？" |
| **情报中心** | 事件时间轴、分类筛选、事件详情（含Diff） | "竞品发生了什么变化？" |
| **AI报告** | 周报列表、报告详情（核心摘要+重点变化+统计） | "这段时间到底发生了什么？" |
| **趋势分析** | 变化频率、类型分布、AI趋势判断、竞品对比 | "市场往哪个方向发展？" |
| **设置** | 账户信息、AI配置（模型/API Key）、通知方式 | "系统怎么按我的习惯运行？" |

## 四、全局性改进建议

### 1. 信息架构微调

| 当前导航 | 建议导航 | 理由 |
|---|---|---|
| 情报事件 | **情报中心** | 为将来扩展更多情报类型预留空间（流程文档已建议） |

### 2. 跨页面跳转规则（数据关联）

这是流程文档强调但当前设计未充分体现的，建议增加以下跳转：

| 场景 | 点击后跳转 |
|---|---|
| Dashboard 的 "OpenAI 价格变化" | → 情报中心该事件详情 |
| Dashboard 的 "AI今日洞察" | → AI报告/趋势分析 |
| 竞品管理的 "变化：5条" | → 情报中心（已筛选该竞品） |
| 情报事件的 "OpenAI" | → 该竞品详情 |
| AI报告的 "涉及竞品：8" | → 竞品管理（已筛选） |
| 趋势分析的 "查看情报 →" | → 情报中心（已筛选对应类型） |

### 3. 增加空状态设计

当前所有页面都是数据满载状态，实际用户首次使用时需要引导：

| 页面 | 空状态设计 |
|---|---|
| Dashboard | "还没有监控任何竞品，添加第一个竞品开始追踪市场动态" + [添加竞品] |
| 情报中心 | "暂无情报事件，系统会在检测到变化后自动展示" |
| AI报告 | "还没有生成报告，监控运行一段时间后将自动生成周报" |
| 趋势分析 | "数据积累不足，需要至少7天数据才能生成趋势分析" |

### 4. 减少"后台感"，增强"产品感"

当前设计偏传统管理后台（表格、筛选、分页），建议：

- **卡片化**：竞品管理用卡片而非表格
- **故事化**：AI报告用叙事结构而非数据堆砌
- **行动导向**：每个页面都有明确的"下一步行动"（如Dashboard的"添加竞品"、情报中心的"导出事件"）

### 5. 高优先级事件即时通知（已落地）

原 23 步流程的「第十阶段 / 通知」现已实现为：**高优先级情报事件在生成时即时单条推送**（邮件或站内日志，由 `NOTIFY_ENABLED` 开关控制），而非只等整批抓取结束后的汇总。

- 通知内容含竞品名、事件类型、摘要与「查看详情」深链（链接地址取 `frontend_base_url` 配置）；
- 批次结束后的汇总通知仍保留，两者互补：汇总覆盖「只有中/低优先级」的批次，单条即时覆盖「需要立即关注」的高优先级变化；
- 推送失败不影响主抓取流程，用户无需每天打开 Dashboard 也能被及时提醒。

> 事件详情抽屉中，「AI 摘要」（事实）与「AI 判断」（推断、标注"仅供参考"）已做成两个分区，与流程第 12 步"事实与推断分离"的要求一致。
