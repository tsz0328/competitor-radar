# 页面设计与信息架构

> 定义各业务页面的职责边界、相互跳转与空状态约定。
> 代码若与本文冲突，以代码为准；本文随页面改动更新。

## 一、整体业务流程

```
添加竞品 → 配置监控页面(官网/定价页/更新日志…) → 手动或定时抓取
                                                     │
                                              Diff 对比(文本相似度)
                                                     │
                                              AI 一次调用(分类 + 摘要 + 判断)
                                                     │
                                              ┌──────┴──────┐
                                          情报事件          快照留存
                                              │
                                    周报 / 趋势洞察(再聚合)
```

数据对象关联链：

```
Competitor（竞品）→ Source（监控页面）→ Snapshot（网页快照）→ Event（情报事件）
                                                                  ↓
                                          Weekly Report（周报） / Trend（趋势洞察）
```

每个对象有唯一"户籍页"（可增删改、权威展示），其余页面只做引用与带参跳转：

| 对象 | 户籍页 | 其它页面只能 |
|---|---|---|
| Competitor / Source | 竞品管理 | 引用展示 + 带 id 跳回 |
| Snapshot | 竞品管理（抓取记录）/ 事件详情（历史快照） | 只读查看 |
| Event | 情报中心（唯一完整列表） | 摘要（≤5 条）/ 带筛选跳转 |
| Report | 周度报告 | 引用入口 |
| Trend | 趋势分析 | 引用入口 |

## 二、页面职责边界

一个页面只回答一个问题，避免相互 encroach（尤其 Event 不要被多个页面"部分实现"）：

| 页面（路由名） | 回答的问题 | 时间口径 | 唯一职责 | 不该承担 |
|---|---|---|---|---|
| Landing `/` | 产品是什么 | — | 价值展示 / 注册入口 | 不展示业务数据 |
| Login `/login` | 我是谁 | — | 登录注册（含「记住我」：勾选＝长期登录态存 `localStorage`，不勾＝仅本次会话存 `sessionStorage`） | — |
| 工作台 Dashboard | 今天有什么需要我处理 | 今天（自然日） | 异常/重点分发台，只给"去处理"入口 | 不做分析、不做全量列表、不做长期趋势 |
| 竞品管理 Competitor | 监控谁、是否健康 | 当前态+今天 | 配置与运维（增删改、抓取、启停） | 不展示历史情报细节 |
| 情报中心 Event | 到底发生了什么 | 近 7 天（可切） | 唯一事实库，所有"看证据"都回这里 | 不做结论、不做对比 |
| 周度报告 Report | 这段时间发生了什么、能交出去 | 自然周/月 | 可交付产物（生成/收藏/分享/导出） | 不做即时性内容 |
| 趋势分析 Trend | 长期往哪走 | 7/30/90 天 | 判断与对比 | 不承载当日待办 |
| 设置 Setting | 系统按什么规则跑 | — | AI 模型、抓取偏好、用户中心（昵称/账号/邮箱/头像） | 不展示业务数据 |
| 顶栏 TopBar（横切） | 有没有需要我处理的事 | — | 通知中心：铃铛 + 未读角标 + 下拉面板 | 不做检索（跨页搜索已移除，检索留在各页面内） |

三条设计原则：

1. 同一目的地 + 同一筛选状态，在工作台上只出现一次。
2. 指标卡负责"进明细"（点击进列表）；内容区块的条目点开抽屉看详情，不再另给出口。
3. 从工作台出发的跳转必须带"今天"上下文，否则卡片数字与落地列表对不上。

## 三、工作台当前结构（自然日口径）

工作台只回答"今天"，当前结构（已落地）：

- **4 张指标卡**（点击进对应页面，落点各不相同）：
  - 监控竞品 → `Competitor`
  - 今日情报 → `Event?date=<今天>`
  - 重点变化 → `Event?date=<今天>&priority=high`
  - 风险提醒（今日舆论动态）→ `Event?date=<今天>&category=negative`
- **近 30 天趋势图**：导航型，点某天 → `Event?date=<该天>`
- **今日要点**：左 AI 结论 + 右证据列表（高/中优先级 ≤5 条），条目点开详情抽屉；底部"今日分布"chips 仅展示、不可点
- **竞品动态**：今日有变化的竞品行可点 → `Event?competitorId=<X>&date=<今天>`；无变化的行不可点
- **空态**：未添加竞品时引导「添加竞品」→ `Competitor`

## 六、减少"后台感"、增强"产品感"（约定）

已落地、继续遵循：卡片化（竞品管理支持卡片视图）、故事化（周报 Markdown 正文 + 摘要结构）、行动导向（每页有"下一步"按钮：工作台添加竞品、情报中心导出/重置、周报生成/分享/下载）。

事件详情的「AI 摘要」（事实）与「AI 判断」（推断、标注"仅供参考"）已分区，符合"事实与推断分离"。

称呼到人：工作台招呼语显示「昵称」（用户中心可改；没单独设置时默认取账号），比笼统的「用户」更有产品感。

## 八、高优先级事件即时通知（已落地，后端）

高优先级情报事件在生成时即时单条推送（邮件或站内日志，由 `NOTIFY_ENABLED` 控制），非整批抓取结束才汇总。通知含竞品名、类型、摘要与「查看详情」深链（取 `frontend_base_url`）。批次结束后的汇总通知仍保留，互补覆盖"只有中/低优先级"的批次。推送失败不影响主抓取流程，用户无需每天打开工作台也能被及时提醒。
